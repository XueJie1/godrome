# Godrome：低内存原生客户端验证计划

## 1. 目标与边界

先完成可运行的最小原型，验证 **MyGO 原生 UI + 内嵌 libmpv** 是否适合长期开发。

- 功能：单服务器登录、专辑列表、专辑曲目、歌曲搜索、播放队列、播放/暂停、上下曲、进度拖动和音量。
- 格式：MP3、FLAC、AAC、Opus；使用系统默认音频输出。
- Navidrome 优先，调用标准 Subsonic/OpenSubsonic 接口。
- 本阶段不做离线下载、歌单编辑、歌词、托盘、系统媒体控制、无缝播放和自动更新。喜爱使用 Subsonic `star`/`unstar` 与 `getStarred2`，不在本机另存一份。
- Linux 完成实际运行和内存测量；Windows/macOS 完成构建与自动测试，真实桌面验收暂列待完成。

## 2. 技术与界面方案

**技术栈**

- Go + MyGO `ui`，从官方 native 模板建立项目。
- 普通 Go 包承担业务逻辑，不另建服务器。
- `net/http` 请求 API；libmpv 直接获取音乐流，避免 Go 再缓存一份音频。
- 使用 libmpv 官方 C API，通过小型 Go/cgo 适配层调用；不启动 mpv 子进程，不自行实现解码器。[mpv 文档](https://mpv.io/manual/stable/)
- 原型使用系统安装的 libmpv。各平台提供明确的依赖安装说明；动态库缺失时显示可理解的错误。
- 本阶段不引入数据库。JSON 保存服务器地址、用户名、音量、窗口尺寸、侧栏宽度、队列宽度、主题色、外观和均衡器。密码默认写入操作系统密钥环，登录一次后自动登录；退出登录删除。token 和带认证的 URL 只留在会话内存中。
- 首次建立项目时固定 Go、MyGO 和依赖版本，并记录 libmpv 版本与许可证；不随每次构建自动升级。

**界面**

- 中文界面，跟随系统深浅主题、字体与缩放；不加入玻璃效果或背景模糊。动效只标记一次状态变化：封面出现、错误或状态出现。系统要求减少动态效果时直接到位。不加入循环或装饰性动画。
- 登录页使用现成输入框、记住密码勾选和按钮。默认记住密码。
- 主窗口：左上角为 Godrome，其右侧是后退和前进；左侧为曲库、专辑、喜爱、歌单、设置，每项带图标，侧栏变窄时只留图标；顶部搜索；中部专辑封面网格或曲目列表；右侧播放队列，窗口窄于 860 时折叠为提示并在变宽后恢复；底部固定播放控制，音量旁是扬声器图标。拖到 0% 或点击图标会静音，再点击恢复静音前的音量。窗口窄于 900 时扬声器先展开音量滑条。设置页用外观、声音、账号三个标签分类。外观用太阳、月亮和显示器表示浅色、深色和跟随系统，并可改主题色；声音调节十段均衡器和预设，窄窗口可横向滚动到每一段。退出登录在账号标签，不在侧栏底部。底部可轮换顺序播放、列表循环和单曲循环，并显示或隐藏右侧队列。左右分隔条用框架的 Split 拖动，侧栏不窄于 64、不宽于 360，窄于 140 时收起文字和标题、只留图标，图标保留提示和名称；队列不窄于 200、不宽于 480。页眉只写页面名，不重复侧栏已经标明的位置，也不借用第一首歌曲。曲库按每页 100 首列出，并写本页数量。搜索写本次返回的数量。专辑详情用专辑自己的封面和艺人。专辑封面按可见项请求 256 像素图，网格只构建可见行。封面和标题作为一组，在选中高亮里水平居中。封面尚未到达时显示静音方块和图标。喜爱用歌曲、喜爱专辑、喜爱艺人三个标签列出服务端已标记的内容，专辑和艺人只构建可见项；歌曲行和专辑详情标题下方可以标记或取消喜欢，专辑详情的心形与标题左对齐，专辑网格不放喜欢按钮。歌单尚未接入，空状态说明从左侧回到曲库。后退和前进按浏览器历史移动：新的页面访问清掉前进记录，同一页面不重复入栈，同一次搜索不按每次按键入栈。返回时回到离开前选中的歌曲。
- 优先复用 `ui.List`、`TextInput`、`Button`、`Slider`、`Image` 和布局组件；只组合业务视图，不重写基础控件。
- 使用框架虚拟列表，只构建可见行；封面在后台解码一次，不在每帧解码。[列表文档](https://github.com/egoist/mygo/blob/main/docs/ui/list.md)、[图片文档](https://github.com/egoist/mygo/blob/main/docs/ui/image.md)
- 沿用默认主题参数和主题颜色，避免另建样式体系。[主题文档](https://github.com/egoist/mygo/blob/main/docs/ui/styling.md)

## 3. 模块、数据流与内存约束

**模块接口**

| 模块 | 职责与最小接口 |
|---|---|
| API 客户端 | 登录验证、分页专辑、专辑详情、搜索、喜爱、标记喜欢、封面、生成播放地址；请求接受 `context.Context` |
| 播放引擎 | `Load`、`Pause`、`Seek`、`SetVolume`、`Stop`、`Close`；输出状态、进度、结束和错误事件 |
| 播放队列 | 保存曲目及当前索引；上下曲、选择播放、正常结束后自动下一曲 |
| 应用状态 | 接收请求及播放结果，在主线程更新 UI；视图不执行网络或阻塞工作 |

- API 使用用户名、随机盐和 token 认证；密码、token、带认证参数的地址不写入日志。
- 支持服务器 URL 的路径前缀。连接错误、认证失败、空列表分别呈现；保留正常 TLS 验证。
- 搜索延迟 300 ms 发起，取消旧请求，丢弃过期结果；请求页面离开后取消后台任务。
- 播放状态区分加载、播放、暂停、缓冲、结束和错误；播放失败保留队列，由用户重试或下一曲。
- 使用 libmpv 属性事件驱动状态更新；进度显示最多每秒更新两次，暂停和隐藏时停止进度刷新。
- 退出时取消网络请求，结束事件循环并销毁播放器，避免残留资源。

**内存控制**

- 专辑分页每页 100 条；最多保留最近五页。专辑详情和搜索结果随页面替换释放。
- 封面请求使用缩略图，解码后缓存上限 8 MiB，并限制下载并发为 2；切换服务器清空缓存。
- libmpv 按需初始化，关闭视频、脚本、用户配置和外部媒体自动加载；设置有限的音频预读与缓存，初始前向缓存上限 4 MiB、后向缓存为零。
- 不把整首音乐下载到内存；不通过频繁 GC 强行压低测量数字。
- CPU/GPU 渲染沿用 MyGO 默认策略，同时记录驱动加载前后的占用；仅用 CPU 模式进行诊断比较。

## 4. 开发顺序与 SDLC

采用指南中的版本化产物与持续验证流程，按原型规模实施。[SDLC 指南](https://claude.com/resources/articles/the-ai-native-sdlc-playbook)

1. **固定意图与约束**：建立 `intent.md`、`spec.md`、`plan.md`，记录本计划、组件选择和验收标准；统一 Claude/Codex 的仓库指导。
2. **验证技术底座**：建立原生空窗口和 libmpv 适配层；先完成本地四种格式的播放、暂停、拖动与退出，测空窗口和播放器基线。
3. **完成在线闭环**：实现登录、分页浏览、搜索、队列及流播放；加入加载、空数据和错误状态。
4. **验证与优化**：增加业务测试、原生 UI 测试、Linux 实际操作与内存测量；只针对测量发现的问题优化。
5. **交付原型报告**：提供源码、构建产物、依赖说明、测试结果、截图、内存数据和已知限制；据此制定正式客户端下一阶段计划。

提供统一的构建、检查、测试和内存测量入口。每项任务完成前运行相关检查并保留证据；不以编译成功代替实际播放验收。本阶段不配置公开发布或自动上传。

## 5. 验收与测量

**功能测试**

- 模拟 API 验证认证、URL 前缀、分页、搜索取消、超时和错误响应。
- 使用 MyGO `ui.NewTester` 验证登录、选曲、队列、播放状态和错误展示；检查键盘操作、深浅主题与缩放。
- 使用自生成音频样本验证四种格式、拖动、暂停恢复、自然结束与快速切歌。
- 使用临时 Navidrome 测试实例验证真实 API 和原始格式流播放，不依赖个人账号。
- Linux 真实桌面确认声音、拖动进度、连续播放及正常退出；CI 的无声输出测试单独标明。

**内存测量**

- 使用 release 构建，固定窗口尺寸、缩放、样本曲库及 libmpv 版本；每个场景运行三次。
- 测量空窗口、浏览曲库、滚动加载封面、四种格式播放、暂停、连续切歌 30 分钟。
- Linux 报告进程 RSS/PSS、Go 堆、CPU、线程数、峰值及稳定值；记录显示和驱动环境。libmpv 占用包含在应用进程中。
- 用一万条模拟曲目验证虚拟列表；反复浏览和切歌后，占用应趋于稳定，不能出现持续累积。
- 本阶段不预设 100/150 MiB 上限。交付测量基线、主要成本和下一阶段预算建议；Windows/macOS 内存数据缺失时明确标为未测。

**原型完成条件：** Linux 在线播放闭环和上述验证通过，Windows/macOS 构建及可执行的自动测试通过，内存报告可复现。三端真实运行通过后，才宣称三端运行兼容。
