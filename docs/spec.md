# 最小实现规格

本规格把 `intent.md` 的原型计划落实为一个可运行闭环，不扩大产品范围。

功能范围汇总见 [scope.md](scope.md)，实现与验收细节以本规格和 `intent.md` 为准。

## 可观察行为

- 登录前显示完整服务器地址、用户名、密码，并默认勾选记住密码；认证失败和网络失败可辨识。
- 登录成功列出专辑，按名称排列，每页 100，最多缓存最近五页；上一页、下一页、刷新可操作。
- 打开专辑释放上一页面的曲目；歌曲搜索在最后一次输入 300 ms 后执行，取消旧任务并拒绝过期结果，最多返回 100 首。等待期间保留上一批结果，并标明正在搜索的查询；过期响应不覆盖新查询。同一次搜索连续改字只保留一条历史。清空搜索回到进入搜索前的页面。
- 专辑为虚拟封面网格，歌曲和队列为虚拟列表；选择支持框架键盘操作，Enter 打开/播放。窗口聚焦时，空格播放、暂停或继续当前曲目；焦点在文本输入、按钮、开关等自己处理空格的控件上时，空格留给该控件。空格不再用于滚动页面。格子比封面宽时，封面和标题作为一组在选中高亮里水平居中。歌曲列表和队列列表可以用滚轮滚动，下一帧仍停在滚过的位置。列表右侧都为滚动条留出位置，选中高亮不与滚动条重叠。
- 页眉只写页面名和数量，不借用第一首歌曲。曲库写「本页 N 首」和第几页，并可播放本页。搜索写「搜索结果」、当前查询和「本次返回 N 首」；达到 100 首时写「最多显示 100 首」。没有结果时写「没有找到与「查询」匹配的歌曲」。只有专辑详情显示专辑封面、专辑艺人和喜欢按钮，封面与艺人来自专辑而不是第一首歌曲，并有「播放」。封面尚未到达时是静音方块和图标，不显示字符；封面到达后淡入。播放进度条随底栏宽度伸缩，最短 160、最长 560。歌单显示「还没有这一页。从左侧回到曲库。」
- 喜爱读取 `getStarred2`，用歌曲、喜爱专辑、喜爱艺人三个标签列出已标记内容，专辑用虚拟网格，艺人用虚拟列表，只构建当前标签的可见项。歌曲行和专辑详情标题下方的心形调用 `star`，再次点击调用 `unstar`；歌曲用 `id`，专辑用 `albumId`，艺术家用 `artistId`。专辑网格不放喜欢按钮。心形没有按钮底。歌曲行的心形和更多图标为 14，靠在列表右边界，并在行内垂直居中；选中高亮仍停在滚动条左侧。专辑详情的心形在标题下方，与标题左对齐，不在页眉里水平居中。页面较窄时封面改到标题上方并缩小，心形仍留在标题下方。喜欢状态只留在本次会话，不写入配置。本地文件没有喜欢。服务端确认取消后，喜爱页去掉该项；写入失败则恢复标记并显示错误。三类都空时写「还没有喜爱。在歌曲或专辑上标记喜欢。」某一类为空时写该类自己的空状态。
- 错误和状态文字进入时下移到位，离开时淡出。
- 左右分隔条使用框架的 Split，指针可拖，分隔条获得焦点后方向键也可移动。侧栏宽度限制在 64 到 360。侧栏的曲库、专辑、喜爱、歌单、设置各有图标；窄于 140 时收起文字和 Godrome 标题，只留居中的图标轨道，图标仍有悬停提示和辅助技术名称。队列显示时，右侧分隔条拖动队列，宽度限制在 200 到 480。窗口窄于 860 时不把队列停靠在右侧，改为折叠提示，不改用户的显示意图和已保存宽度；窗口变宽后恢复。关闭窗口时和窗口尺寸一起保存这两个宽度。
- Godrome 标题右侧有后退和前进。后退回到上一次页面访问，前进回到后退离开的页面。打开另一个页面后，前进记录被清掉。同一页面再次打开不新增记录。离开页面时记下选中歌曲的 ID，返回后按 ID 滚回该行；找不到时用原来的序号。历史不保存歌曲数组、封面或认证地址。退出登录清空历史。播放、队列和音量不进入历史。
- 侧栏有设置。设置页用外观、声音、账号、存储四个标签分类。外观用太阳、月亮和显示器表示浅色、深色和跟随系统。主题色的自定义颜色和预设色都是圆点。自定义颜色仍打开取色器。声音调节十段均衡器和预设；窗口较窄时十段可以横向滚动，不裁掉频段。退出登录只在账号标签，停止播放、删除已保存密码并释放会话。主题色、外观、均衡器和缓存设置留在配置里，下次启动恢复。跟随系统不覆盖系统外观。
- 专辑封面后台请求 256 像素图，两名 worker，32 个待处理请求，解码缓存上限 8 MiB。离开页面即取消和释放该页的内存缓存；封面原始字节和专辑、歌曲、喜爱元数据同时写入用户缓存目录，返回页面或重新启动时优先从磁盘读取。
- 网络失败而缓存可用时，页面显示上次缓存的数据，顶栏显示数据库对勾图标，悬停和辅助技术名称为「离线缓存」，不显示文字。认证失败和 HTTP 4xx 不回退。设置可以关闭离线回退。启动时若服务器不可达、首页专辑已缓存且离线回退开启，则直接进入上次的曲库并显示图标；没有缓存时停在登录页显示连接错误。音频不缓存，离线时不能播放未缓存的歌曲。
- 存储标签提供「离线时显示缓存」开关、缓存上限（128 MiB、256 MiB、512 MiB、1 GiB）、已用空间和「清除缓存」。清除只删除磁盘内容，当前已显示的页面保留到离开；上限改变后立即按最近使用时间淘汰。
- “播放”把当前曲目页复制为队列并从所选曲目开始；“加入队列”追加。队列支持选曲、上下曲，正常 EOF 自动下一曲；错误保留队列。
- 显示加载、播放、暂停、缓冲、结束、错误；暂停/恢复、进度 Slider、音量、停止、重试均可操作。底栏音量旁是扬声器图标，滑条名称仍是「音量」。拖到 0% 或点击图标会静音，图标改为划掉的扬声器，滑条也到 0。静音时再点击图标，恢复静音前的音量。窗口窄于 900 时先隐藏滑条，点击扬声器展开滑条，再拖到 0 静音。
- 登录成功且记住密码仍勾选时，把密码写入系统密钥环。下次启动若地址、用户名和已保存密码都在，自动登录一次。认证失败则清除已保存密码并停在登录页，不再重复尝试。取消勾选后再登录会删除已保存密码。退出登录停止播放、删除已保存密码并释放会话。关闭应用取消请求，结束引擎 goroutine，销毁 mpv handle。
- Linux 下在会话总线注册 `org.mpris.MediaPlayer2.godrome`，对象路径为 `/org/mpris/MediaPlayer2`。桌面媒体组件可读取曲名、歌手、专辑、封面、总时长、播放进度、播放状态和循环模式，并在应用窗口隐藏时继续得到前进的进度；可播放、暂停、播放/暂停、停止、上一曲、下一曲、拖动进度、设置音量和切换循环模式。歌曲结束后，组件看到的状态与队列自动续播一致。没有会话总线时 MPRIS 不出现，应用照常运行。

## 技术约束

- Go 1.27.1、MyGO v0.2.15；官方 native 模板建立，纯 Go 业务模块，cgo 调用 libmpv C API。
- libmpv 延迟初始化，通过动态库加载。系统缺失依赖显示中文错误，不启动 mpv 子进程。
- token 为 Subsonic 指定的 MD5(password+随机盐)，每次请求使用新盐；TLS 验证正常，跨源和协议改变的 HTTP 重定向被拒绝。
- 请求默认超时 15 秒，JSON 响应上限 4 MiB，封面下载上限 1 MiB，图片解码前限制尺寸。内存只放固定 256×256 位图；磁盘只保存原始封面字节和元数据 JSON。
- 磁盘缓存位于用户缓存目录，键为「服务器 + 用户名」命名空间加资源 ID，不包含 token 或认证 URL；文件名是键的哈希，索引不保存原始键。总上限按封面与元数据 7:1 分配，元数据至少 16 MiB；按最近使用时间做 LRU 淘汰，超过上限时降到 90%。写文件使用临时文件加 rename，索引原子重写；索引缺失或损坏时从目录重建，不整库删除。
- 音频 URL 直接交给 libmpv，`format=raw`；关闭视频、外部文件自动加载、用户配置和脚本。前向缓存 4 MiB，后向 0，音频预读 5 秒。
- libmpv 事件在单独 worker 处理；事件包含播放代次，过期 EOF 不推进新队列。进度最多 2 Hz，暂停、隐藏或最小化不刷新进度 UI。MPRIS 的 `Position` 在两次上报之间按播放状态外推，暂停、缓冲或结束时不前进。
- MPRIS 是同一进程内的会话总线服务，不启动后台进程。只暴露曲名、歌手、专辑、封面、时长、进度和传输状态；带 token 的流地址不交给总线。封面写入同一磁盘缓存，以 `file://` 地址提供。没有会话总线时静默跳过。
- JSON 配置只保存服务器、用户名、音量、窗口尺寸、侧栏宽度、队列宽度、主题色、外观、均衡器、缓存上限和离线回退开关。密码由操作系统密钥环加密保存，不写入该文件。token、认证 URL 和音频不持久化；封面和元数据只以哈希文件名保存在用户缓存目录，可随时清除。
- 沿用 MyGO 主题、字体、缩放和渲染策略，无自建控件或循环动画。封面出现、错误或状态出现使用一次过渡，时长 180 ms；系统要求减少动态效果时直接到位。

## 最小交付验收

1. Linux release 构建、vet、业务/原生 UI race 测试通过。
2. MP3/FLAC/AAC/Opus 通过 libmpv 播放、暂停恢复、seek、自然结束、快速替换和错误测试。无声输出单列。
3. 模拟 API、一次临时 Navidrome、用户明确提供的测试服务器完成在线闭环。
4. Linux 实际原生窗口正常启动/退出，系统默认输出有音频信号；附截图和三次短时内存数据。
5. Windows/macOS 仅报告本次真正执行的编译检查；原生 cgo 构建/测试提供 CI，未运行不宣称通过。

完整原型仍需完成 `intent.md` 的完整内存场景（含四格式与 30 分钟连续切歌）、Linux 桌面验收，以及 Windows/macOS 原生构建和可执行自动测试。本次最小交付不替代这些条件；三端真实桌面运行均通过后，才宣称三端运行兼容。
