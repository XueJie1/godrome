# 功能边界

本文件汇总现有文档的范围，不新增产品需求。产品目标与约束以 [intent.md](intent.md) 为准；最小实现行为以 [spec.md](spec.md) 为准；完成状态与证据见 [plan.md](plan.md)、[report.md](report.md)。

## 产品定位

Godrome 当前是验证 **Go + MyGO 原生 UI + 进程内 libmpv** 的低内存音乐客户端原型。面向 Navidrome，使用标准 Subsonic/OpenSubsonic 接口，先完成单服务器在线听歌闭环，并测量真实资源成本。

## 本阶段包含

| 功能 | 边界 |
| --- | --- |
| 登录与会话 | 单服务器地址、用户名、密码；支持 URL 路径前缀；区分认证失败与网络失败；退出登录停止播放并释放会话 |
| 专辑浏览 | 按名称分页，每页 100 条，最多缓存最近五页；上一页、下一页、刷新、打开专辑查看曲目 |
| 歌曲搜索 | 仅搜索歌曲；输入停止 300 ms 后发起，取消旧请求并丢弃过期结果，最多返回 100 首 |
| 列表与封面 | 专辑、歌曲、队列使用虚拟列表；支持框架键盘选择与 Enter 打开/播放；显示受限缓存的专辑缩略图 |
| 播放队列 | “播放”用当前曲目页建立队列并从所选曲目开始；“加入队列”追加；队列选曲、上下曲、正常结束自动下一曲；错误保留队列 |
| 播放控制 | MP3、FLAC、AAC、Opus；系统默认音频输出；暂停/恢复、进度拖动、音量、停止、重试 |
| 状态反馈 | 加载、播放、暂停、缓冲、结束、错误；连接错误、空列表和依赖缺失有可理解的提示 |
| 界面与设置 | 中文原生界面，跟随系统主题、字体和缩放；仅保存服务器地址、用户名、音量、窗口尺寸 |
| 本地播放入口 | 已有命令行打开本地音频的辅助入口；本阶段不扩展为本地曲库管理 |

## 本阶段不包含

现有文档明确排除：离线下载、歌单编辑、收藏、歌词、托盘、系统媒体控制、无缝播放、自动更新。侧栏的「喜爱」和「歌单」目前只保留入口，尚未接服务器数据。

以下能力未列入现有最小规格，也不在本阶段自动扩展：多服务器管理、歌手浏览、专辑/歌手搜索、队列删除/重排、随机/循环播放、本地曲库扫描。若需要，应另行定义行为与验收。

不引入 Web UI、独立后台服务、数据库、mpv 子进程或自建解码器；不重写基础 UI 控件，不加入持续动画、玻璃效果或背景模糊。不公开发布或自动上传。

## 必须保持的约束

- 密码、token、认证 URL 只存在于会话内存，不进入配置、源码、日志或测试证据；不持久化曲目和封面。
- 保持正常 TLS 验证、请求超时与 context 取消；网络、图片解码、libmpv 初始化和命令在后台执行，UI 通过 `Window.Update` 更新。
- 保持分页、封面缓存和后台任务上限：封面 256×256、两个 worker、32 个待处理请求、8 MiB 解码缓存；页面离开时取消任务并释放对应缓存。
- 音频由 libmpv 直接取流，不将整首歌曲下载到内存；前向缓存 4 MiB、后向缓存为零、预读 5 秒；进度 UI 最多 2 Hz，暂停或隐藏时停止刷新。
- 使用固定依赖版本及系统 libmpv；播放构建启用 cgo，动态库缺失显示中文提示。
- 不强制 GC 美化数据，不预设 100/150 MiB 硬性内存上限，以可复现测量确定后续预算。

## 验收边界

| 层级 | 可以得出的结论 |
| --- | --- |
| 最小交付 | 按 `spec.md` 验证在线闭环、四格式播放器、Linux 原生启动/退出与输出信号，并提供三次短时内存基线；各项证据分别报告 |
| 完整原型 | 按 `intent.md` 补齐 Linux 桌面操作、完整三次内存场景和 30 分钟连续切歌，以及 Windows/macOS 原生构建和可执行自动测试 |
| 三端运行兼容 | Linux、Windows、macOS 三端真实桌面运行验收均通过后，才使用这一表述 |

无声输出测试、UI tester、无 cgo 跨平台编译、真实桌面操作不能互相替代。短时内存基线不能证明长期稳定性。

后续补充验收已完成 Linux 真实桌面自动化输入与用户听感确认，以及独立 headless 原生窗口的完整三次内存矩阵和 3×30 分钟切歌，见 [acceptance.md](acceptance.md)。Linux 物理键盘/鼠标人工全流程、Windows/macOS 原生构建/自动测试与桌面播放仍保留待验收。
