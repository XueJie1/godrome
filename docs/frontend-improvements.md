# 前端改进分析与实施建议

日期：2026-10-11。状态：P1 已于 2026-10-12 落地，见 [spec.md](spec.md) 与 [acceptance.md](acceptance.md)。P2、P3 仍是设计建议。

分析基线：提交 `8af725775b43358978e10ec4b88369e45bfe2359`，MyGO `v0.2.15`。本文件承接前端审查，说明现状、问题、官方 example 的可借鉴做法以及具体实施路径。它不把建议提前记为已实现行为；落地时需同步修改 [spec.md](spec.md)、[intent.md](intent.md) 和 [acceptance.md](acceptance.md)。

## 1. 结论、证据与边界

现有基础组件选择合理：Sidebar、Split、List、GridView、Tabs、Slider 已承担原生交互；网络和封面处理有取消与容量限制。建议继续组合框架组件，优先改善内容空间、页面语义、浏览连续性和喜爱页的构建成本。

本次审查包括源码、官方 main 分支 examples 目录与 gallery 源码，以及本地 Go 模块缓存中的固定版本示例。引用以固定版本链接为准。官方示例展示 API 用法，并不是音乐客户端的产品规范；下文明确区分“示例做法”和“Godrome 建议”。

已执行的针对性检查：

```sh
GODROME_UI_EVIDENCE=/tmp/godrome-ui-review CGO_ENABLED=1 go test . \
  -run 'Test(SettingsLookAndEqualizer|LoginAndOnlineViews|StarWritesAndStarredPageReads|AlbumStarSitsUnderTheTitle)$' \
  -count=1
```

四项测试通过。查看了生成的 `albums.png`、`queue.png`、`settings.png`，包含浅色专辑/队列和深色设置界面；另生成深色与 150% 缩放截图。临时截图不作为持久验收证据。本次没有进行真实桌面操作、音频测试或长期内存测量，也没有测得窄窗口溢出量；窄布局、喜爱页缓存抖动等结论属于源码推导，需在实施时复现验证。

保持以下约束：

- Go + MyGO 原生 UI + 进程内 libmpv，不引入 Web UI、服务或数据库。
- 固定依赖版本；以下核心方案不以升级 MyGO 为前提。
- 保留分页、最近五页专辑数据、封面两名 worker／32 个待处理请求／8 MiB 解码缓存。
- UI 状态通过 `Window.Update` 更新；后台任务接受取消；不持久化曲目、封面、浏览历史、token 或认证 URL。
- 不增加玻璃、模糊和装饰循环动画，不扩展到歌词、歌单编辑、托盘或系统媒体控制。
- 本文中的新行为是实施建议；原型当前范围仍以已有规格为准。

## 3. P1：三栏和底栏的空间分配

已落地，2026-10-12。下面保留当时的问题和分析。

### 当前实现

[app.go](../app.go) 的 `view` 使用两个 Split：外层划分侧栏与主体，内层划分内容与队列。`queueVisible` 默认开启；侧栏默认 220，范围 160–360；队列默认 280，范围 200–480。`main.go` 设置最小窗口 800×560。

`clampColumns` 给中间区域保留的计算下限仅约 40 DIP，而主内容还有左右共 44 DIP 的内边距。`pageWidth` 最低返回 48，但这个返回值不会给真实布局增加空间。`controlsView` 中曲目信息宽 220、音量滑条宽 110，另有封面、多个按钮和间隔。`equalizerSection` 的十列各宽 46、九个间隔各 4，共 496 DIP，未计容器内边距。

### 当前问题

两侧栏各自合法不代表中间内容可用。最小窗口下拖宽侧栏和队列，会挤压标题、歌曲操作和均衡器。底栏固定区域也可能在封面出现、长标题和缩放时竞争空间。这是待复现的布局风险，不能用当前 1080 宽截图宣称 800 宽已经验收。

### 官方示例与建议

E1 使用弹性内容列和 `MinWidth(0)`，E3 使用 `Wrap()`，E8 展示 Popover。它们提供布局工具，但 gallery 本身也有固定宽度区域，并没有完整的三栏响应式方案。

建议把“用户希望显示队列”和“当前宽度允许显示队列”分开。主内容获得可用空间优先于展开队列；音量在紧凑模式进入 Popover；均衡器使用水平 Scroll，保持全部频段可操作。

### 具体怎么改

1. 在 `view` 构建前统一计算布局模式，避免各处分别推导宽度。初始建议主内容净宽至少 320 DIP，另加其 44 DIP 内边距；这是待实测调整的设计值。
2. 先将侧栏限制在 160–360，再计算队列可分配宽度。若剩余空间不足以同时容纳主内容、分隔线和最小 200 的队列，临时折叠队列；用户请求显示时可用框架浮层呈现队列。所有 `pageWidth`、Split 和切换按钮使用同一“实际布局模式”。
3. 自动折叠不覆写用户的队列显示意图和保存的偏好宽度；窗口变宽后恢复。侧栏同样区分保存值与因窗口变窄而产生的有效宽度。
4. 底栏曲目信息改为可收缩、有最大宽度的列；核心播放按钮保持可见。紧凑模式由扬声器按钮打开音量 Popover，静音语义必须仍有明确入口。
5. 用 `ScrollHorizontal` 包裹均衡器十段控件。只有这一固定数量区域横向滚动，不以普通 Scroll 代替大列表虚拟化。
6. 外观选择、主题色预设行允许换行。边栏标题与前进后退在最小侧栏宽度下单独检查。

### 验收

- 800×560、1080×720、1440×900；浅深主题；100%、150%、200% 缩放。
- 拖动两侧分隔条至上下限，队列开关来回切换，放大后恢复用户意图。
- 长中文标题、长拉丁标题、正在播放封面出现时，主播放按钮和列表操作仍可点击。
- 十个频段均可用鼠标及键盘到达，无不可恢复的水平裁切。

## 4. P1：搜索、曲库和专辑页头部分离

已落地，2026-10-12。下面保留当时的问题和分析。

### 当前实现

`songView` 处理曲库、搜索、专辑和本地音频页。艺人取 `a.songs[0].Artist`，封面取第一首歌曲的 `CoverArt`；除本地和曲库以外都显示大封面，因此搜索页也显示大封面。`openAlbum` 保存歌曲与专辑名，没有单独保存完整的专辑头部模型。

### 当前问题

搜索结果可能横跨多个专辑和艺人，却被第一首结果的封面与艺人代表；曲库头部同样可能错误暗示属于第一首的艺人。`len(a.songs)` 是本页数量，不是整个曲库总量。空搜索结果没有关键词提示。专辑实际元数据与第一首歌曲信息也不一定相同。

### 官方示例与建议

E1 按路由分别调用页面函数，并为各页面设置自己的标题；E6 展示数据列的独立表达。示例没有音乐专辑头部，建议借鉴其“页面负责自身语义”的结构。

建议保留共用 `songList`，拆分 `libraryHeader`、`searchHeader`、`albumHeader`、`localHeader`。曲库表格属于后续可选项，不作为修复错误页头的前置条件。

### 具体怎么改

1. `songView` 按 screen 调用独立头部函数；仅专辑详情展示专辑大封面和专辑喜欢按钮。
2. `openAlbum` 成功后保存小型 `albumHeaderData`，包含 ID、名称、艺人和封面 ID。离开专辑页释放；封面 ID 不等于认证 URL。
3. 搜索头部显示“搜索结果”、当前查询和“本次返回 N 首”；达到 100 条时说明“最多显示 100 首”，不能直接断言还有更多结果。
4. 曲库显示“本页 N 首”或明确的序号范围及页码，不显示第一首艺人。空搜索显示“没有找到与……匹配的歌曲”；空曲库和空专辑用各自文案。
5. 专辑页增加清楚的“播放”按钮，复用 `playSongs(0)` 的队列替换语义；曲库若提供批量入口，应写“播放本页”，避免误认为播放全库。加载或空数据时禁用。
6. 保留详情心形在标题下方左对齐的现有约定。

### 验收

模拟搜索返回来自不同专辑的两首歌，确认页头没有第一首封面或艺人；曲库翻至第二页，数量不冒充总数；无结果和 100 条上限有正确文案；专辑播放按钮建立的队列与现有列表播放行为一致。

## 5. P1：浏览位置和搜索历史

已落地，2026-10-12。下面保留当时的问题和分析。

### 当前实现

[nav.go](../nav.go) 的 `place` 保存 screen、分页 offset、专辑 ID/名称和 query，历史最多 100 条。`beginPage` 清空选中项并重建 `ListState`、`GridState`。`goBack` / `goForward` 重新加载页面。

`SearchField.Changed()` 调用 `search`，再调用 `searchNow`；后者在等待 300ms 前已经 `visit()` 并 `beginPage()`。因此每个输入变化都可能进入历史，而且立即清空旧结果。清空搜索固定返回专辑页，而不是进入搜索前的页面。

### 当前问题

从专辑详情后退后，要重新寻找刚才的位置。输入一个多字符查询可能需要连续后退多次才能离开搜索。防抖取消保护了请求正确性，但没有解决历史和视觉连续性。

### 官方示例与建议

E1 的 Router 示例保留页面滚动状态；E5 使用稳定 Key 和 `ScrollTo`。框架 API 还有 [ListState.Visible / ScrollTo](https://github.com/egoist/mygo/blob/v0.2.15/ui/list.go#L153-L181) 与 [GridState.ScrollTo](https://github.com/egoist/mygo/blob/v0.2.15/ui/gridview.go#L47-L56)。

建议第一阶段保留现有历史实现，加入小型恢复书签和搜索历史替换操作。不要直接把 Router 的保留视图机制套在整个业务页面上，否则需要额外核对视图闭包、曲目与封面是否被历史长期引用。

### 具体怎么改

1. 给历史项增加恢复信息：选中业务 ID、首个可见歌曲 ID及备用索引。离页前保存，返回且请求成功后按 ID 找位置，再调用 `ScrollTo`；只在恢复时调用一次，不能每帧强制滚动。
2. 历史项仍最多 100 个，不保存歌曲数组、Bitmap、Cache、context 或带认证地址，也不复制带数据闭包的完整 ListState。
3. v0.2.15 的 GridState 没有公开 `Visible()`。第一阶段可恢复被打开/选中的专辑，不能宣称像素级恢复滚动位置；若需要精确视口恢复，另行评估框架公开 API 支持。
4. 数据变化或 ID 消失时钳制备用索引；页面空时不调用无效的 `ScrollTo`。网格恢复在列数确定后进行，覆盖窗口宽度改变的情况。
5. 为 `history` 增加有测试的“替换当前搜索项”操作。第一次进入搜索新建一项；同一次搜索会话连续修改 query 替换这一项；跳转到其他页面后再次搜索建立新项。后退后开始新搜索仍须清除前进分支。
6. 单独保存进入搜索前的页面标识；清空搜索返回该页面，不能递归记录新的搜索项。退出登录清空全部恢复信息。
7. 将“输入变化”和“提交搜索请求”分开。输入后立刻取消旧请求并使其结果失效；300ms 后开始新请求。等待时可暂留上一批结果，但必须标明正在搜索新的查询，并阻止旧结果被当作新结果提交播放。

### 验收

专辑网格滚动后打开详情再后退、曲库翻页后往返、连续输入与快速删除、输入中文时的组合输入、后退后产生新查询、请求乱序返回、目标歌曲消失、退出登录清历史。历史长度不能随同一查询的每次按键增长；旧响应不能覆盖新查询。

## 6. P1：喜爱页虚拟化和资源边界

已落地，2026-10-12。下面保留当时的问题和分析。

### 当前实现

`showStarred` 一次获取 `getStarred2` 的歌曲、专辑、艺人。歌曲使用 `songList`；艺人与专辑使用 `ScrollHorizontal` 加全量 for 循环。每个专辑都会调用 `coverArt`，后者调用页面封面缓存的 `Get`。

### 当前问题

横向 Scroll 裁切屏幕内容，但并不让 for 循环只构建可见项。收藏多时 UI 树随数据量增长；不可见专辑也参与封面排队，可能在有限 LRU 下不断重取被淘汰项。缓存仍有硬上限，因此应称为多余构建/请求风险，不能未经测量称为已证实内存泄漏。

### 官方示例与建议

E7 明确使用一万项 GridView 展示可见项构建；E5 展示虚拟 List。建议喜爱页采用“歌曲／专辑／艺人”三个 Tabs：歌曲 List、专辑 GridView、艺人 List，仅构建当前分类。

### 具体怎么改

1. 增加 `starredTab` 和独立的分类选择/滚动状态，不与普通专辑网格状态混用。
2. 专辑复用卡片和 GridView；艺人使用紧凑 List 行，保留取消喜欢入口，不新增歌手详情功能。
3. 为每个分类设置稳定 Key、Label、Selected；专辑支持 Enter 打开，艺人取消喜欢有明确键盘入口。
4. 封面查询仅在 GridView 的可见项回调发生；继续共用当前页的有界缓存，不给每个收藏单独创建 worker。
5. 取消喜欢成功后移除项目并修正选中项；失败恢复状态。各分类显示独立数量和空状态。
6. 本方案只限制构建和图片工作，不把 `getStarred2` 变为分页 API；返回数组的内存和 4 MiB 响应上限仍需单独观测。不要通过无限增加响应上限解决收藏过多。

### 验收

UI fixture 注入 10,000 个收藏专辑，记录首帧/滚动后的构建项数、唯一封面请求数和缓存字节数。停留不滚动时请求应趋于停止；构建项数应随视口而不是总收藏数增长。API 测试另用符合响应上限的 fixture。反复切分类、取消喜欢、离页时验证取消及资源释放。

## 7. P2：加载、错误和播放器操作层级

### 当前实现

`message` 使用共享 `errorText` 和 `status` 在搜索栏下显示文字。页面加载通过 `beginPage` 清空列表并显示“加载中…”。播放错误也写入 `errorText`。加入队列只调用队列 Add。底栏始终排列循环模式、上一曲、暂停/继续、下一曲、重试、停止；无播放时主按钮仍选用暂停图标，只是禁用。

### 当前问题

页面请求与播放错误共用反馈位置和字符串，错误归属不清晰，页面跳转也可能清掉播放错误。加入队列缺少确认。低频操作持续占用底栏，空闲暂停图标不能表达“尚未开始播放”。正在缓冲与已经失败应具有不同操作。

### 官方示例与建议

E3 的 `Toast` 用于已完成动作；E8 的 Popover/Menu 承载次要操作，并展示可撤销 Toast。建议短暂成功提示与持续错误分开：加入队列用 Toast；页面错误留在页面并提供对应重试；播放错误留在底栏。不要将需要用户处理的错误只做成自动消失的 Toast。

### 具体怎么改

1. 分离页面状态、播放错误、设置保存错误；错误保留纯安全文本和动作标识，不保存认证 URL。页面重试按当前 place 重新请求，并继续使用 requestID 防过期。
2. 空列表仅在请求成功且数据为空时显示；失败时不能同时写“没有歌曲/专辑”。加载提示放在稳定的页面状态区域，避免顶部插入文字导致列表上下跳动。
3. 加入队列成功后在事件发生那一帧调用 `c.Toast("已加入队列")`；不要在每帧 view 中重复发出。后台完成提示先进入一次性 UI 事件，再由 UI 消费。
4. 底栏主按钮按 Idle、Loading、Playing、Paused、Buffering、Ended、Failed 分别定义图标、标签、禁用与动作。Idle 且无队列显示禁用播放；Paused 显示继续；Failed 显示重试；Playing 显示暂停。已有曲目停止后的播放动作复用 `playCurrent`。
5. Loading 与 Buffering 时保留真实状态提示，是否允许暂停依播放器支持确定；不能借图标变更伪造播放成功。
6. 停止收进“更多”菜单；失败时重试可直接出现。循环模式、队列、上下曲仍可发现。原“重试”测试按新的状态入口改写，不删除实际重试覆盖。

### 验收

API 失败后重试、播放失败同时浏览页面、设置保存失败、连续加入队列、停止后重新播放、缓冲时切歌。错误不会被无关动作覆盖；Toast 每个动作只出现一次；队列在播放错误后保留。涉及播放控制的实现改动额外运行 `make test-audio`。

## 8. P2：键盘、右键与当前歌曲定位

### 当前实现

歌曲/队列已有 List 的选择与 Submitted，专辑已有 GridView 的 Submitted；按钮设置了 Label/Tooltip。因此已有 Enter 和框架双击提交能力，不应把“双击播放”列为完全缺失功能。歌曲菜单目前通过每行“更多”按钮打开；没有窗口内搜索快捷键和定位当前播放入口。

### 当前问题

频繁操作依赖移动到小图标。队列较长时，当前播放项可以在视口之外。空格若直接设为全局播放快捷键，会与输入框、按钮及 Slider 交互冲突。

### 官方示例与建议

E4 使用 `c.Shortcut(ui.Cmd, ui.KeyF)`；E5 在行上设置 ContextMenu，并使用 ScrollTo。建议补充窗口范围快捷键和复用菜单，不注册系统级全局快捷键。

### 具体怎么改

1. Ctrl/Cmd+F 聚焦当前页面顶部搜索输入；搜索包装函数要返回实际可聚焦的输入元素，不能假设外层容器的 Focus 自动作用于内部编辑器。
2. 抽取歌曲菜单构建函数，供“更多”和行 ContextMenu 共用。动作读取对应 song ID/index，并在执行前检查仍属于当前页，防止异步换页后索引过期。
3. 队列标题加入“定位当前歌曲”，只在有当前索引时可用；调用 `queueList.ScrollTo(index, ui.Center)`，不改变选曲或开始播放。
4. 切歌时仅在用户原本跟随当前项时自动滚动，或第一阶段完全使用显式定位按钮，避免打断正在浏览历史队列的用户。
5. 播放快捷键先采用不会吞掉文本输入的组合键；若增加空格播放，需验证焦点路由、事件消费和输入法行为。避免直接全窗口拦截空格。
6. 重复的“更多／喜欢”辅助标签带上歌曲标题，帮助键盘测试和辅助技术区分目标；视觉 Tooltip 可保持简短。

### 验收

纯键盘搜索、列表 Enter、原有双击、右键打开菜单、Escape 关闭、长队列定位。输入中文/空格时不触发播放；定位不切歌；相同歌曲重复加入队列仍按队列索引定位。

## 9. P2：登录表单和搜索中文化

### 当前实现

`loginView` 直接排列 TextInput，设置 Label 和 Placeholder，没有用可见 Field 标题。统一错误显示在表单底部。`topBar` 调用 `SearchField(...).Label("搜索歌曲").Placeholder("搜索歌曲")`，但本次截图仍显示 `Search`。

原因已核对：v0.2.15 的 [SearchField 实现](https://github.com/egoist/mygo/blob/v0.2.15/ui/combobox.go#L376-L415) 给内部 `TextInputBase` 写入 `Placeholder("Search")`，返回外层字段容器；[Element.Placeholder](https://github.com/egoist/mygo/blob/v0.2.15/ui/editor.go#L786-L792) 只在目标元素有 editor 时生效。因此外层 Placeholder 未改变内部文字。内部清除按钮标签也为 `Clear`。

### 当前问题

占位文字在填写后消失，字段名称不够稳定；Label 主要负责语义，不等于可见标题。服务器地址格式错误、空用户名和认证失败没有清楚的字段归属。搜索中文化不能只凭源码出现中文字符串验收。

### 官方示例与建议

E4 用 Form/Field 区分名称、描述和错误。建议登录沿用 TextInput 与 Password，外包 Form/Field；搜索在固定版本下用框架输入框、Icon 和 Button 组合一个薄业务组件，不重写编辑器、焦点系统或输入法。

### 具体怎么改

1. 登录建立“服务器地址／用户名／密码”可见 Field；服务器字段提供路径前缀示例；错误使用 Field.Error。密码不放进错误文本或测试截图。
2. 本地校验仅检查必填和可接受 URL 结构；请求成功前不能假定凭据有效。密码不 TrimSpace，不改变用户实际输入。
3. 登录中禁用重复提交并显示“正在登录”；保留记住密码默认勾选、自动登录一次及失败处理的原语义。
4. 新建 `searchInput` 组合函数，用真正的 TextInput 设置中文 Placeholder/Label，放置放大镜和带“清除搜索”标签的按钮，返回 changed/submitted/实际输入元素供聚焦。
5. 对照 SearchField 原实现保持清除后焦点、Escape 行为、空值按钮可见性和输入法。若直接用普通 TextInput 不能保留搜索角色语义，记录这一差异并评估可用公开 API；不要通过访问框架私有 editor 修补。
6. 另一条路线是推动框架提供公开的 SearchField 本地化接口，但升级必须单独说明原因和版本；本轮不依赖尚未发布 API。

### 验收

空字段、本地格式错误、认证失败、网络失败、自动登录、密码含首尾空格、Enter 提交；截图确认中文搜索占位文字；清除后焦点仍可输入；辅助标签没有英文 Clear。密钥环仍用 mock，真实钥匙串另验收。

## 10. P3：视觉一致性、可选表格与源码组织

### 当前实现与问题

SidebarItem 的图标参数为 nil；各页头部字号、间距分散在函数内。`applyTheme` 已集中处理强调色，但固定白色 AccentText 配合任意自定义主题色，存在浅色强调背景下对比不足的风险。`app.go` 约两千行，同时承载请求、导航、设置、布局和列表。

歌曲列表目前是标题／艺人两行，宽屏下未展示专辑列；这不属于正确性问题。把它全面换成 Table 会改变信息密度和交互，宜作为后续独立选择。

### 官方示例与建议

E2 提供图标侧栏；E6 展示 Table 的列、稳定 Key 和排序；gallery 的 `card` 使用 Theme 的 Surface/Text/Border 等语义颜色。建议先统一业务视图的少量样式和辅助函数，再考虑宽屏表格，不建立新的控件或主题系统。

### 具体怎么改

1. 在 `icons.go` 增加曲库、专辑、喜爱、歌单、设置的统一线性图标；直接传给 SidebarItem。当前只有五项，无需为了模仿 gallery 增加可折叠分组和统计徽标。
2. 提取页面标题、空状态、歌曲操作菜单和封面卡片的业务组合函数；仍使用框架 Button/List 等原语。
3. 深浅主题及预设、自定义浅色强调色下检查选中行、按钮文字、焦点环对比。优先使用框架公开的主题配色能力；必要时集中计算适合强调背景的前景色，不在各行散落硬编码补丁。
4. 若增加宽屏 Table，初始列为歌曲、艺人、专辑、时长；窄屏仍用现有两行列表。切换布局保留选中业务 ID；排序只对当前页有效时必须明确标注，不能假装全库排序。多选和批量编辑不自动加入范围。
5. 功能落地后再按职责移动为 `view_shell.go`、`view_library.go`、`view_player.go`、`view_settings.go`、`view_login.go`，文件名是建议。小步移动，避免重构同时改动全部行为。

### 验收

侧栏鼠标和方向键仍正常；长标题截断不挤掉操作；强调色调整后选中项和焦点可辨。可选 Table 另定义排序、宽度与小窗口验收，不作为首轮完成条件。纯文件移动只需已有检查，不增加镜像实现的测试。

## 11. 实施顺序、修改映射和交付标准

| 批次 | 范围 | 主要修改位置 | 交付标准 |
| --- | --- | --- | --- |
| A | 三栏、底栏、均衡器空间 | app.go 的 view、宽度函数、controlsView、equalizerSection | 最小尺寸与缩放矩阵通过，队列展开意图可恢复 |

每批先补可观察行为规格，再与代码、必要测试、文档放在同一次提交。本文保持设计记录，完成后标记对应章节的落地提交与验收位置，不以删除问题描述掩盖决策过程。可选 Table 不纳入 A–D。

### 文档同步

- `spec.md`：记录实际采用的折叠、搜索历史、分类、快捷键、错误和播放按钮行为。
- `intent.md`：更新界面布局与交互方案，不改变原生架构和资源约束。
- `acceptance.md`：记录真实执行的方法、环境、结果、截图和测量，不提前勾选。
- `scope.md`：落地时检查与规格的一致性；当前“随机/循环播放”仍被一并列为未纳入范围，但实现已有三种顺序/循环模式，需要单独对齐表述，不能因此误增随机播放。

### 检查与测试

基础命令为 `make build check test`；播放控制或播放器相关改动追加 `make test-audio`。构建遵守 cgo 要求，不使用默认禁用 cgo 的 `go tool mygo build`。本次仅新增设计文档，不声称已运行这些完整检查。

优先扩展已有测试：`TestHistoryButtonsReturnToThePreviousPage`、`TestSearchDebounceCancellationAndStaleResults`、`TestVirtualSongList`、喜爱往返测试、`TestKeyboardLoginBrowseQueueAndControls`、侧栏/队列分隔条与滚动条高亮测试。新增用例针对前述真实回归场景，不逐行复制实现逻辑。

性能验收记录可见构建数、封面请求数、缓存字节数、goroutine 和实际进程内存。固定 fixture、窗口、缩放及渲染方式；不主动 GC。大量收藏测试不能只断言数组长度，要验证不滚动时不可见封面不会持续下载。

最后分别报告：UI tester、libmpv 无声输出、跨平台无 cgo 构建、真实桌面输入与声音。任何一类通过均不能代替其他类。短时浏览数据不作为 30 分钟稳定性结论。
